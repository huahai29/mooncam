# 跨平台一致性

本页说明 Windows 与 Linux 上同一算例为何必须给出同一答案，比较如何做，以及哪些差异不属于缺陷。

## 要解决的问题

同一份 MoonBit 代码会在不同操作系统、不同 Node.js 版本上编译与运行。若结果随平台变化，那么截图、报告和注册表版本都失去可复现性。常见来源是：

- 换行符（`\r\n` 与 `\n`）导致文件摘要不同；
- 路径分隔符与绝对路径进入报告；
- 双精度数字在转换字符串时末位取舍不同；
- 不同数学库实现导致 `sin`/`atan2` 末位差异。

前两项属于表示差异，必须在比较前消除；后两项才是真正的数值差异，必须能被发现而不是被静默吞掉。

## 清单内容

`tests/consistency.mjs` 在每台机器上对固定算例生成 `artifacts/consistency/manifest-<platform>-<arch>.json`：

1. 五组算例：仓库自带的四个示例，外加一组自定义的混合规律算例（三种规律混用、负偏置、非整数转速、分辨率 720）。
2. 每组装配 `points`、`csv`、`svg`、`dxf` 后取引擎输出。
3. 规范化：换行统一为 LF；JSON 按对象键排序、数组保持顺序；所有数值取 15 位有效数字；报告中的 `input` 回显被移除。
4. 对 JSON、CSV、DXF、SVG 分别计算 SHA-256，得到 `canonical_sha256`；同时保存未规范化的 `raw_sha256`，用于区分“逐字节相同”和“数值等价”。
5. 另外用 `bin/mooncam.mjs` 真实写出 `profile.csv`、`profile.dxf`、`profile.svg`、`input.json`，对其分别取规范化摘要，确认落盘路径与内存路径一致，且平台换行不会混入比较。

清单还记录 `platform`、`arch`、`node` 与 `.moonbit-version` 中的编译器版本，便于判断差异来自代码、Node 还是工具链。

## 比较规则

`tests/consistency.check.mjs <目录>` 读取该目录下所有 `manifest-*.json`：

- 默认本地模式允许只有一份清单，明确提示未执行跨平台比较并返回 0；清单本身和 CLI 成功条件仍须有效。
- CI 显式传入 `--require-platforms=win32,linux`，必须同时收到这两个平台的清单；缺失、重复同一平台/架构或空清单均失败。不同架构的两个 Windows 清单不能替代 Linux。
- 每份清单都要求 CLI 的 `ok=true`、退出码为 0、五个输出文件齐全及摘要有效。两边同时失败也判失败，不将“同样失败”解释成一致。
- 多份清单时，逐算例比较四类产物的规范化摘要。全部一致则报告“identical”。
- 若规范化摘要一致但原始摘要不同，报告“字节摘要不同、规范化摘要一致”，说明差异只在末位数字或换行，不影响数值结论。
- 规范化摘要不一致时仍判失败；同时以 `1e-12` 数值容差检查摘要指标，补充字段级诊断。状态字符串不一致也失败。清单未保存完整导出坐标，不能声称这里进行了完整坐标的容差回退比较。

CI 中 Windows 与 Ubuntu 分别生成清单并上传，独立作业下载后统一比较；不一致即失败，Pages 部署也被阻断。

## 不属于缺陷的差异

- **不同后端**：本仓库只承诺同一后端在不同操作系统上一致。Native 后端使用不同的数学库，`sin`/`atan2` 的末位可能与 JS 不同，判定验收中明确不要求四后端逐位一致。
- **末位取舍**：规范化到 15 位有效数字，低于该精度的差异不会让比较失败，但会在 `raw_sha256` 中体现。
- **不同 Node 大版本**：CI 固定 Node 22；升级 Node 属于环境变更，应同时更新清单并说明原因。
- **浮点环境策略变化**：改变浮点收缩、重排或次正规数处理策略时，必须重新生成清单并复核 G05/G14 等临界用例，不能沿用旧结论。

## 本地复现

```sh
npm run build
node tests/consistency.mjs
node tests/consistency.check.mjs artifacts/consistency
```

单机运行时第二步会提示“只有一份清单”。要真正比较，需要把另一平台的清单放进同一目录，或从 CI 的 `mooncam-validation-*` artifact 中取出 `manifest-*.json`。

## 门禁回归与性能检查

`npm run test:consistency:checker` 包含 9 组比较器回归用例，覆盖平台缺失、重复身份、CLI 双失败、输出和摘要缺失、空清单、状态/数值/摘要差异及允许的原始字节差异。CI 在两平台均运行。

CI 在 `npm run benchmark` 之外执行 `npm run performance:check`：前者记录观测，后者对摘要体积、固定负载结果和宽松耗时上限执行门禁，两者不互相替代。

严格比较命令：

```sh
node tests/consistency.check.mjs artifacts/consistency --require-platforms=win32,linux
```
