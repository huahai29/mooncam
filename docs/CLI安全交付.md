# CLI 文件交付与失败恢复

CLI 默认拒绝已有输出目录，包括空目录。选择新的 --out 路径；批量运行时每项子目录分别发布，整批不是一个原子事务。

## 发布流程

1. 小型 JSON 配置用同一打开的文件描述符读取，前后核对文件身份、大小、修改与状态时间；路径替换或读取期间变化报错。解析后使用同一内存快照，之后的源文件编辑不影响本次输入与报告。
2. 在输出的同级目录独占创建 .mooncam-lock 预留，再创建随机 .mooncam-stage-* 暂存区，记录操作令牌与进程身份。
3. 各文件独占创建，写入、同步并关闭。关闭成功后记录摘要；所有文件成功后再重命名为正式目录。任一步失败不发布半套结果，保留暂存用于检查。
4. 不自动删除进程中断留下的锁，也不自动覆盖既有结果。

正式目录中的 owner.json 是本地交付元数据，不是引擎计算报告。只在同一文件系统、可信本地父目录内使用。协议排斥遵守本协议的 MoonCam 并发进程；最后一次检查到 rename 之间，无法防止不遵守协议的外部进程新建空目录，不宣称跨平台具备通用 rename-no-replace 原语。fsync 文件不等于目录项断电持久性；网络文件系统、断电与恶意目录替换不在保证范围。

## 检查与清理

```sh
node scripts/staging.mjs list PARENT
node scripts/staging.mjs clean STAGE TOKEN
```

先只读列举。清理要求令牌匹配、进程已不存在、所有权记录有效、仅包含登记的普通文件且摘要未变；PID 已复用、进程状态不明、未登记的部分写入、文件被改或额外文件都拒绝自动清理，保留人工检查。仅逐个删除验证过的文件，不递归删除目录树。空锁或损坏的所有权记录同样保留人工处理。正式目录不能被暂存清理命令删除。

## 故障验证

8 组 tests/delivery.test.mjs 覆盖既有目标、写入/同步/关闭/重命名注入失败、发布前目标出现、源文件读时变化、读后快照独立、真实子进程强制终止、另一进程竞争、活动任务拒清、错误令牌与额外文件拒清、死进程暂存清理及重试。注入通过测试专用 I/O 适配器进行，不在生产 CLI 中开放故障环境变量。
